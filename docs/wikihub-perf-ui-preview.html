06rail 入口特写（48px 内 11 项）

新增项放在「运行日志」之后，与知识类入口用一条 1px 分隔线隔开。激活态是 3px 左侧竖条 + 品牌色 14% 底，与现有 10 项完全一致。
尺寸 / 规格取值来源

新增图标仪表盘（三段弧 + 指针），与既有 10 项同一网格新增 IconGauge
图标不用现成图标库：既有 10 个图标全是 stroke 描边、1.6px、24 网格手写的， 混进一个填充式图标会在 17px 下明显不同粗细。IconGauge 约 4 行 path。

07与现有视图的关系（不放代码，只放边界）

这张表是给实现和评审对齐用的：哪些是复用、哪些是新增、哪些是有意不做。
对象处理理由
工具栏（48px sticky）完全不动全屏只能有一个 data-dsh-workbench-toolbar，性能视图不能再造一条
rail加 1 项 + 1 条分隔线11 项仍在一屏内（11 × 38 ≈ 418px）
左栏本视图换内容，宽度/折叠/拖拽行为不变性能视图里目录树不是导航对象；但拖拽与自动折叠策略不改
阶段切换条复用 .whTabs，仅加一个 16px 圆底数字/勾四步是一条流水线，用 tab 表达进度比四张并列卡片清楚
指标卡复用 .whGrid + .whStat概览视图已经在用同一套，尺寸无需改
事件流复用 .whLogRow 列宽（64 / 108 / 自适应）和运行日志同一阅读节奏，用户不用重新学
图表手写 SVG（VU 曲线 / 趋势线）+ CSS 宽度条包体预算只剩约 91 KB，引图表库直接超
报告正文复用 src/lib/markdown.js不出现第二套 Markdown 渲染
深色主题零额外代码全部走 --dsw-alias-*，亮暗切换不需要分支
窄容器perfDuo 在 < 760px 叠成一栏用 container query，不用 window media query（工作台宽度与窗口宽度无关）
